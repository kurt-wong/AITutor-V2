## 1. 产品定位

AI Tutor Personal Edition 是一个家庭自用、面向高中学生的题库管理与智能辅导平台。

核心价值：

- 管理员上传高中教师版 PDF/DOCX 真题，系统自动提取题目、配图、答案、详解和元数据。
- 题库支持精细元数据分析、频次统计、趋势分析和知识点占比分析。
- AI 根据历史趋势、频率和占比生成新题，经管理员审核后入库，并支持导出练习/试卷。
- 学生上传 JPG 错题，系统自动识别并形成错题本。
- 系统根据错题和知识点掌握度生成针对性练习，自动判分并记录学习过程。

---

## 2. 用户

### 2.1 管理员

管理员是系统的主要维护者。

职责：

- 批量上传教师版 PDF/DOCX。
- 审核低置信度解析结果。
- 维护题库、题型规范、知识树和系统配置。
- 查看统计分析。
- 触发 AI 组卷/生成练习。
- 审核学生 JPG 错题。

### 2.2 学生

学生是系统的主要使用者。

职责：

- 登录后直接进入学习页面。
- 上传错题 JPG。
- 查看错题本并一键重练。
- 做系统生成的练习。
- 查看自己的学习趋势和薄弱点。

### 2.3 权限

- 需要简单登录。
- 至少区分管理员和学生两类角色。
- 当前按单学生家庭场景设计，不实现多学生账号。

## 3. 核心需求

### 3.1 文档入库

支持的输入：

- 带文字层的教师版 PDF。
- 排版规范的教师版 DOCX。
- 扫描版或图片型 PDF。

扫描版和图片型 PDF 也需要处理，但识别结果按低置信度进入人工校对。

答案和详解支持两种位置：

- 统一放在文档末尾，按题号反查。
- 紧跟每道题后面，就近匹配。

解析输出以 Question Aggregate 为准，包括：

- 题干
- 选项
- 答案
- 详解
- 配图
- 元数据

数学、物理、化学中的几何图、电路图、装置图、函数图等需要独立截取，并与题目一一对应。如果题目本身是图片，则保留原图，同时尽量提取图片中的文本。

高优先级科目：

- 数学
- 物理
- 化学
- 英语
- 语文
- 生物
- 政治

其他科目支持入库，但精度要求可适当降低。

### 3.2 元数据

元数据与试题内容分开存储。

元数据字段：

| 字段 | 说明 |
|---|---|
| 学科 | 数学、物理、化学、英语、语文、生物、政治等 |
| 年级 | 高一、高二、高三 |
| 年份 | 题目/试卷来源年份 |
| 学校 | 来源学校或试卷名称中的学校信息 |
| 题型 | 按学科细粒度定义 |
| 分值 | 题目分值，可为空 |
| 难度 | 1-5 级 |
| 知识点 | 映射到标准知识树节点 |
| 出现次数 | 单题跨文档出现次数，以及知识点/题型按年份出现频次 |

试题内容字段：

| 字段 | 说明 |
|---|---|
| 题干 | 题目正文 |
| 选项 | 选择题选项 |
| 答案 | 标准答案 |
| 详解 | 解答过程或解析 |
| 配图 | 与题目关联的图片资源 |

公式和特殊符号：

- 内部使用结构化公式表示。
- 页面显示和导出时渲染为正常印刷体。
- 用户不直接看到 LaTeX 源码。

### 3.3 题型

- 题型采用细粒度定义。
- 题型规范按学科维护。
- 题型规范供识别、统计、组题共用。

### 3.4 知识点体系

- 使用管理员提供的标准考点表、教材目录或现有知识树。
- 可以先生成初版，再逐步修正。
- AI 只能映射到已有节点，不能随意创建新节点。

### 3.5 去重与合并

- 同一道题在多份试卷中出现时自动识别并合并。
- 保留多个来源信息。
- 保留出现次数。
- 查重采用文本规则 + embedding 语义相似度。

### 3.6 AI 生成题

AI 生成题需要：

- 根据考点趋势、频率和占比生成新题。
- 生成完整题目、选项、答案、详解。
- 需要公式/配图时支持生成或生成后人工补充。
- 不依赖固定试卷模板。
- 系统根据历史比例自动决定结构。
- 保留管理员手动设定比例和结构的能力。
- 支持导出学生版试卷，答案和详解单独导出。

AI 生成题管理：

- AI 生成的新题经管理员审核后长期入库。
- 标记为“生成题”，与“真题”区分。
- 生成题与真题一起参与查重、统计和组卷，但可按类型筛选。
- 只保留“生成题”类型标记，不额外记录生成模型、审核人等来源信息。

### 3.7 学生错题

学生上传 JPG：

- 自动切分为多道题。
- 每道题单独识别。
- 优先匹配题库已有题目；已有则关联，没有才新建。
- 新建/识别结果进入管理员待确认队列。
- 管理员确认时可修改题干、选项、答案、详解。
- 系统自动记录错题出现次数和频率。

错题统计：

- 同一道题被孩子做错的次数。
- 同一知识点或题型错题出现次数。

### 3.8 学生练习

触发方式：

- 学生主动点击练习。
- 系统根据最近错题主动推荐。
- 管理员后台手动生成。

判定规则：

- 优先系统自动判分，例如选择题和可判定填空。
- 不能自动判分的题型后续由学生或管理员补录。

练习记录：

- 保存题目、孩子答案、对错、用时、知识点。
- 系统练习中答错的题自动进入错题本。

重复出题：

- 允许重复，尤其是高频考点和薄弱点。
- 根据孩子答题记录动态调整，已掌握题少出，薄弱点多出。

### 3.9 统计分析

管理员和学生都需要查看统计分析。

统计维度：

- 题型频次与年份趋势。
- 知识点频次与占比。
- 难度分布。
- 错题统计。
- 学生学习趋势和薄弱点变化。

时间范围由管理员自行设置，不固定。

### 3.10 审核与准确率

- 大量入库依靠自动化。
- 前期通过充分测试，把自动解析准确率提高到 95% 以上。
- 只对低置信度题目进入人工校对。
- 文档处理需要展示任务进度、失败原因、失败重试、解析日志和低置信度详情。

## 4. 非目标

以下内容不作为当前开发范围：

- 多孩子独立账号和复杂权限。
- 手机、平板端。
- 题库批量 Excel/Word 导入导出。
- 固定模板模拟考试系统。
- 复杂学习计划、打卡、社交等泛教育功能。
- 对外 SaaS 或多租户服务。

## 5. 前端设计

前端页面遵循 `Docs/Design.md` 的设计风格。

必须遵守：

- 单一蓝色强调色。
- 页面主体以白色/浅灰/近黑全宽区块为主。
- 不使用装饰性渐变和多余阴影。
- 卡片、按钮、表单、表格等组件保持一致的设计语法。
- 管理端偏工具型布局，学生端偏清晰、安静、内容优先。

具体页面和组件规范见 `Docs/02_Architecture/UI.md`。

## 6. 验收标准

| 指标 | 目标 |
|---|---|
| 题目切分准确率 | 98% |
| 题干提取准确率 | 98% |
| 题号识别准确率 | 98% |
| 答案匹配准确率 | 95% |
| 详解匹配准确率 | 90% |
| 配图关联准确率 | 90% |
| 学科/年级/年份/学校元数据 | 95% |
| 题型识别准确率 | 95% |
| 知识点映射准确率 | 85%，低置信度人工修正 |
| 自动通过题目无需修改比例 | 95% |
| 100 道题人工审核时间 | 10 分钟内 |

同时必须满足：

- 文末答案和题后答案都能正确匹配。
- 数学/物理/化学配图能独立截取并关联。
- 重复题能合并，来源信息作为 Question Instance 保留。
- 支持按管理员设置的时间范围统计。
- AI 能按趋势、频率、占比生成新题。
- 生成题经审核后入库并标记为生成题。
- 支持导出学生版，答案和详解单独导出。
- JPG 多题能自动切分，错题匹配或新建后进入管理员确认队列。
- 练习自动判分，答错自动进错题本。
- 错题本支持列表、详情、重练、标记已掌握和统计。

## 7. 开发阶段路线

产品范围保持完整，开发按依赖关系分阶段推进。

### Phase 0：基础工程

- FastAPI 骨架。
- PostgreSQL、MinIO、Redis、Docker Compose。
- Repository、Domain Service、Application Service 分层。
- 统一 Background Task。

### Phase 1：题库核心

- 上传 PDF/DOCX。
- 文档解析。
- Question Aggregate。
- 人工审核。
- 入库与查看。

### Phase 2：搜索、统计与知识

- 条件搜索。
- 去重。
- embedding。
- 知识点映射。
- 统计分析。

### Phase 2.5：AI 生成实验

- 只做简单单题生成实验。
- 输入知识点、题型、难度。
- 输出一题、答案、解析。
- 不自动入库，仅用于验证知识体系。

### Phase 3：学生错题

- JPG 上传。
- OCR/VL 识别。
- 匹配或新建。
- 错题本。

### Phase 4：练习与推荐

- 自动判分。
- 掌握度。
- 学习记录。
- 针对性推荐。

### Phase 5：AI 生成与导出

- 趋势/频率/占比驱动的完整 AI 出题。
- 审核后入库。
- 学生版和答案详解版导出。
