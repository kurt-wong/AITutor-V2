## 1. 目标与定位

系统定位是：**家庭自用、面向高中学生的题库管理与智能辅导平台**。

核心目标：

1. 管理员批量上传高中教师版 PDF/DOCX 真题文档，系统自动提取题目、配图、答案、详解和元数据，形成可统计、可检索、可组卷的结构化题库。
2. 对题库做精细元数据分析，支持题型频次、年份趋势、知识点频次与占比、难度分布等统计。
3. AI 结合历史趋势、频率和占比生成新题，经管理员审核后入库，并可作为学生练习或试卷导出。
4. 学生上传 JPG 错题，系统自动识别、匹配或新建题目，形成错题本。
5. 系统根据错题、知识点掌握度、历史表现生成针对性练习，并自动判分、记录学习过程。

---

## 2. 用户与权限

系统只有两类角色：

| 角色 | 主要职责 |
|---|---|
| 管理员 | 上传和解析文档、审核低置信度题目、维护题库、查看统计、生成练习/试卷、审核学生 JPG 错题、管理系统配置 |
| 学生 | 电脑浏览器登录，上传错题 JPG、做题、查看错题本和学习统计 |

已确认：

- 需要简单登录，至少区分管理员和学生。
- 当前不支持多学生独立账号，按单个家庭/单个学生场景设计。
- 学生端先按电脑浏览器开发，后期再扩展手机和平板。

## 3. 核心业务规则

### 3.1 文档入库

支持输入：

- 带文字层的教师版 PDF。
- 排版规范的教师版 DOCX。
- 扫描版或图片型 PDF 也支持，但识别结果按低置信度进入人工校对。

文档中答案和详解存在两种位置：

- 统一放在文档末尾，按题号反查。
- 紧跟每道题后面，直接就近匹配。

解析结果需要形成一条完整的结构化题目，包括：

- 题干
- 选项
- 答案
- 详解
- 配图
- 元数据

数学、物理、化学中的几何图、电路图、装置图、函数图等需要从原文档中独立截取，并与对应题目建立明确关联。如果题目本身是图片，则保留原图，同时尽量提取图片中的文本内容。

高优先级科目：数学、物理、化学、英语、语文、生物、政治。

其他科目支持入库，但精度要求可以适当降低。

### 3.2 元数据定义

元数据与试题内容分开存储。

元数据字段：

| 字段 | 说明 |
|---|---|
| 学科 | 数学、物理、化学、英语、语文、生物、政治、历史、地理等 |
| 年级 | 高一、高二、高三 |
| 年份 | 试卷/题目来源年份 |
| 学校 | 来源学校或试卷名称中的学校信息 |
| 题型 | 按学科细粒度定义 |
| 分值 | 题目分值，可为空 |
| 难度 | 1-5 级，LLM 评估并结合学习数据动态修正 |
| 知识点 | 映射到标准知识树节点 |
| 出现次数 | 同一题跨文档出现次数，以及知识点/题型按年份的出现频次 |

试题内容字段：

| 字段 | 说明 |
|---|---|
| 题干 | 题目正文 |
| 选项 | 选择题选项 |
| 答案 | 标准答案 |
| 详解 | 解答过程或解析 |
| 配图 | 与题目关联的图片资源 |

公式和特殊符号：

- 内部使用结构化公式表示。
- 页面显示和导出时渲染为正常印刷体。
- 用户不直接看到 LaTeX 源码。

### 3.3 题型规范

题型采用细粒度定义，并按学科维护。

示例：

- 数学：单选、多选、填空、计算、证明、应用题等。
- 英语：单选、完形、阅读、七选五、语法填空、写作等。
- 语文：默写、文言文、现代文阅读、作文等。

题型规范需要在系统中可配置，供识别、统计、组题共用。

### 3.4 知识点体系

- 使用管理员提供的标准考点表、教材目录或现有知识树。
- 可以先生成初版知识树，再逐步修正。
- AI 只能把题目映射到已有知识点节点，不能随意创建新节点。

### 3.5 去重与合并

同一道题在多份试卷中出现时：

- 自动识别并合并为一道题。
- 保留多个来源信息。
- 保留出现次数。

查重采用两种方式结合：

- 文本规则匹配，例如题干高度相似。
- embedding 语义相似度兜底。

### 3.6 AI 生成题

AI 生成题需要：

- 根据考点趋势、频率和占比生成新题。
- 生成完整题目、选项、答案、详解。
- 数学、物理、化学等需要公式/配图时也要支持生成或生成占位后人工补充。
- 不依赖固定试卷模板，系统根据历史比例自动决定结构。
- 保留管理员手动设定比例和结构的方案。
- 支持导出学生版试卷，答案和详解单独导出。

生成题管理：

- AI 生成的新题经管理员审核后长期入库。
- 标注为“生成题”，与来自原始文档的“真题”区分。
- 生成题与真题一起参与查重、统计和组卷，但可按类型筛选。
- 不额外记录生成模型、生成时间、审核人等来源信息，仅保留“生成题”类型标记。

### 3.7 学生错题

学生上传 JPG：

- 自动切分为多道题，每道题单独识别。
- 优先匹配题库已有题目；已有则关联，没有才新建。
- 新建/识别结果先进入管理员待确认队列。
- 管理员确认时可修改题干、选项、答案、详解。
- 系统自动记录错题出现次数和频率。

错题统计包括：

- 同一道题被孩子做错的次数。
- 同一知识点或题型错题出现次数。

### 3.8 学生练习

练习触发方式：

- 学生进入错题本后主动点击“练习”。
- 系统根据最近错题主动推荐练习。
- 管理员在后台手动生成练习。

判定规则：

- 优先系统自动判分，例如选择题和可判定填空。
- 不能自动判分的题型后续由学生或管理员补录。

练习记录：

- 保存题目、孩子答案、对错、用时、知识点。
- 系统练习中答错的题自动进入错题本。

重复出题策略：

- 允许重复，尤其是高频考点和薄弱点。
- 根据孩子答题记录动态调整，已掌握题少出，薄弱点多出。

### 3.9 学习分析

管理员和学生都需要查看统计分析。

统计维度：

- 题型频次与年份趋势。
- 知识点频次与占比。
- 难度分布。
- 错题统计。
- 学生学习趋势和薄弱点变化。

时间范围由管理员自行设置，不固定为某一固定年数。

### 3.10 审核与准确率

- 大量入库依靠自动化。
- 前期通过充分测试，把自动解析准确率提高到 95% 以上。
- 只对低置信度题目进入人工校对。
- 文档处理需要展示任务进度、失败原因、失败重试、解析日志和低置信度详情。

| 统计分析 | 管理员和学生都要有视图 |
| 趋势时间 | 管理员可配置，不固定 |
| 题库规模 | 5 万题以内 |
| 文档大小 | 单个 50MB |
| 批量上传 | 支持批量，设置合理上限 |
| 部署 | Docker 部署在 NAS |
| 硬件 | NAS 为 CPU，重任务使用云 API |
| 模型分工 | embedding 本地，解析/生成等重任务云 API |
| 云 API | 可以使用 DeepSeek、MIMO、PaddleOCR-VL、PP-StructureV3 |

## 6. 功能范围

### 6.1 管理员后台

1. 文档上传与解析。
2. 批量上传，支持任务进度、失败重试、日志查看。
3. 低置信度题目审核和编辑。
4. 题库查询与筛选。
5. 题型、知识点、难度等元数据管理。

### 6.2 学生端

1. 登录后直接进入学习页面。

## 7. 技术方案

### 7.1 总体架构

建议采用前后端分离架构：

```text
React/Vite 前端
  → FastAPI 后端
  → 领域服务
  → MCP Tool 层
  → PostgreSQL + pgvector / MinIO / Redis
  → LLM Gateway
```

实现层采用 Tool-First / MCP 架构，MCP 工具清单以 `Docs/02_Architecture/MIS.md` 为准。

后端按领域拆分：

- document：文档上传、解析、进度、失败重试。
- question：题目模型、题库、审核、合并。
- knowledge：知识树、知识点映射。
- analytics：频次、趋势、占比、学习分析。
- generation：AI 组题、生成题审核、导出。
- student：学生登录、JPG 错题、练习、学习记录。
- wrong_question：错题本、错题统计。
- system：配置、模型路由、API Key 管理。

### 7.2 文档解析管线

建议按以下流程：

```text
上传 PDF/DOCX
  → 原始文件存储
  → 文本、图片、公式、表格提取
  → 题目切分
  → 配图关联
  → 答案/详解匹配
  → LLM 元数据标注
  → 置信度判断
  → 重复题合并
  → 高置信度入库 / 低置信度人工校对
```

PDF 处理：

- 优先使用 PP-StructureV3 做版面解析和 Markdown 提取。
- 同时读取 PDF 文字层、图片对象和矢量图形。
- 扫描页和图片页走 OCR/VL，输出低置信度题目。

DOCX 处理：

- 读取段落、表格、图片、公式对象。
- 尽量利用 Word 排版结构进行题目切分。

答案匹配：

- 文末答案按题号反查。
- 题后答案就近匹配。
- 无法可靠匹配时进入低置信度审核。

### 7.3 模型分工

| 任务 | 建议方式 |
|---|---|
| embedding | NAS 本地模型 |
| PDF 版面解析 | PP-StructureV3 云 API |
| OCR/VL | PaddleOCR-VL / MIMO / Qwen |
| 元数据标注 | DeepSeek / MIMO |
| 题目生成 | DeepSeek / MIMO |
| 难度评估 | LLM + 规则 + 学习数据 |

所有模型调用统一封装，不写死在业务代码里，后续可切换或新增 Provider。

### 7.4 数据存储

- PostgreSQL：结构化题库、元数据、错题、练习记录、统计。
- pgvector：embedding 和语义查重。
- MinIO 或 NAS 对象存储：原始 PDF/DOCX、配图、学生 JPG。
- Redis：任务队列、缓存、会话。

### 7.5 部署

采用 Docker Compose 部署在 NAS 上：

```text
frontend
backend
worker
postgres
minio
redis
```

NAS 只有 CPU：

- 重任务调用云 API。
- embedding 使用本地轻量模型。
- 本地 LLM 不作为主路径。

### 8.1 用户

## 9. 验收标准

### 9.1 文档解析

- 高优先级 7 个学科的题干、答案、详解、配图关联准确率达到 95% 以上。
- 文末答案和题后答案都能正确匹配。
- 数学/物理/化学配图能够独立截取并关联到对应题目。
- 重复题能够合并，来源信息和出现次数不丢失。

### 9.2 元数据

- 学科、年级、年份、学校、题型、分值、难度、知识点由 LLM 按规范自动标注。
- 低置信度记录进入审核队列。

### 9.3 统计分析

- 支持按管理员设置的时间范围统计。
- 题型、知识点、难度、错题、学习趋势等统计维度可查询。

### 9.4 AI 组题

- 能按历史趋势、频率、占比自动生成新题。
- 生成题经审核后入库，并标记为生成题。
- 支持导出学生版，以及答案和详解独立导出。

### 9.5 学生端

- JPG 多题能自动切分。
- 错题匹配或新建后进入管理员确认队列。
- 练习自动判分，答错自动进错题本。
- 错题本支持列表、详情、重练、标记已掌握和统计。

## 10. 风险与待确认

1. 高准确率不能只靠一个通用模型，需要先用真实教师版文档建立测试集，逐科目验证。
2. PDF 中公式、图片和答案位置差异大，需要设计结构化提取和置信度机制。
3. DOCX 公式、表格、图文混排需要单独验证，不能只依赖文本解析。
4. 同一题不同表述、不同选项顺序的合并，需要文本规则和 embedding 结合测试。
5. AI 生成题的题型、难度、考点合理性需要人工审核闭环。
6. 后续需要确认具体题型规范、标准考点表文件、批量上传单次上限等细节。

## 11. 下一步

1. 根据本文档整理正式需求基线。

4. 验证通过后，再搭建完整前后端平台。
